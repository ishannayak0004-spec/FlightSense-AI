# FlightSense AI for INT395 Supervised Learning

The deployed estimator answers “What did a one-way fare cost for flights like this?” A separate experiment flags expensive economy quotes, and a time-series exercise forecasts the median economy fare across departures on each date. Each question has a different target and a different test.

## Run on a Mac

Use Python 3.12 and run these commands from the project root. The application includes trained weights and practical results, so opening it does not require retraining.

```bash
python3.12 -m venv .venv
source .venv/bin/activate
python -m pip install -r course/requirements.txt
python -m streamlit run course/app.py
```

To reproduce the course figures, download the original archive with the three CSV files. Pass its location to the script. The script writes summaries, predictions, metrics and both plots to `course/results/`. [Flight Price Prediction dataset](https://www.kaggle.com/datasets/shubhambathwal/flight-price-prediction)

```bash
python course/practicals.py ~/Downloads/archive.zip
```

## Where the syllabus appears

| INT395 unit | Project demonstration |
| --- | --- |
| I. Data preparation | Pandas groups 300,153 historical quotes by route and cabin. Seaborn and Matplotlib show how the median changes with lead time. Preprocessors encode categories and scale durations and lead times. |
| II. Classification | A class-weighted logistic regression flags expensive economy quotes. The practical reports precision, recall, F1, ROC AUC and a confusion matrix. |
| III. Ensembles, tuning and interpretation | The fare trainer compares boosted tree configurations and selects a tree/neural mixture on validation data. Permutation importance estimates how each feature contributes to the separate classifier's ROC AUC. |
| IV. Regression | Ridge regression, gradient boosting and a three-hidden-layer neural network estimate a continuous price. The scorecard reports rupee MAE, RMSE, R² and the proportion of predictions within 10% of the observed price. |
| V. Time series | ARIMA and weekly SARIMA forecast the median for the final seven departure dates. Last-observation and previous-week forecasts provide reference points. |
| VI. Pipelines and deployment | Scikit-learn transformations and the classifier are fitted together. The main predictor uses separate fitting, validation, calibration and test groups. Both the interactive Streamlit app and the website load the serialized model weights. |

## Three findings to explain in the viva

**1. A large R² can coexist with meaningful errors.** Differences between economy and business cabins explain substantial price variation. The main model's held-out MAE of approximately ₹2,438 tells a traveller how large an individual error can be on average. The website also displays an interval calibrated using separate examples. A group split by flight number tests generalisation to unseen services within the historical collection. Future market performance requires testing on newer quotes.

**2. A flag for expensive tickets has a measurable trade-off.** The threshold is the 75th percentile of economy prices in the classifier's training set, ₹7,774. At the fitted classifier's default decision threshold, it flagged 8,343 of the 9,836 expensive tickets and incorrectly flagged 5,879 standard tickets. Precision was 58.7% and recall was 84.8%. Training used 164,498 rows and testing used 42,168 rows with disjoint flight numbers. Permuting lead time reduced ROC AUC by 0.267 on the held-out sample. This shows predictive dependence within this dataset. It does not establish that changing an individual booking date causes a particular price change.

**3. A time series needs dates in the right order.** The cleaned table records days before departure. For calendar forecasting the script reads the original economy file, parses actual departure dates and computes one median per day. The first 42 daily medians train ARIMA(1,1,0) and SARIMA(1,1,0)×(1,0,0,7). The last seven days form a single untouched chronological test. SARIMA's MAE was ₹50.39 against ₹63.50 for repeating the last observed value. These errors concern an aggregate across routes and airlines, whose composition can change. The small test window and the absence of a quote-collection timestamp limit operational interpretation.
